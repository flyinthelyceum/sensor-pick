Wire any sensor

An Arduino Nano, one sensor that reads something real, and one thing that answers it. This page gets any sensor from the drawer to numbers on your screen without waiting for Mr. Reasy.

SenseThe sensor turns something physical (distance, light, sound, a touch, a tilt) into a number.
DecideYour code watches the number and picks the line where it starts to matter.
RespondSomething happens: a light, a sound, a motion, or something on screen.

That loop is the whole assignment. Your phone, a car and every game controller run it thousands of times a second.

1Read the labels on your sensor

Every sensor board has tiny labels next to its pins. Find yours in the left column. That tells you where each wire goes.

Unplug the USB cable before you move any wire. Plug it back in when the wiring is done.

2Upload the any-sensor sketch

Paste this into a new Arduino IDE sketch. Change the lines marked CHANGE, then upload (Tools, Board: Arduino Nano). Open Tools, Serial Monitor and set it to 115200. You should see numbers scrolling. Wave a hand, cover it, make a noise: the number should move.

// any-sensor.ino: reads one sensor, prints the number, answers with an LED.

const bool ANALOG = true;    // CHANGE: true if your signal wire is on A0, false if it is on D2
const bool PULLUP = false;   // CHANGE: true only for a bare button or tilt switch on D2
const int  LINE = 500;       // CHANGE: after you watch the numbers, the value where it should react
const int  GAP = 20;         // raise this if the LED flickers at the line

const int LED = 5;           // output: LED long leg to D5, short leg through a 220 ohm resistor to GND
bool over = false;           // remembers the last answer between readings

void setup() {
  Serial.begin(115200);
  pinMode(2, PULLUP ? INPUT_PULLUP : INPUT);
  pinMode(LED, OUTPUT);
}

void loop() {
  int value;
  if (ANALOG) {
    value = analogRead(A0);                     // 0 to 1023
  } else {
    bool on = digitalRead(2);
    if (PULLUP) on = !on;                       // a pressed button reads LOW, so flip it
    value = on ? 1023 : 0;
  }

  if (value > LINE + GAP) over = true;       // clearly over the line
  if (value < LINE - GAP) over = false;      // clearly back under it
  digitalWrite(LED, over ? HIGH : LOW);       // the response

  Serial.print("value ");                      // same format bench.html reads
  Serial.print(value);
  Serial.print(" over ");
  Serial.println(over ? 1 : 0);

  delay(50);                                   // about 20 readings a second
}

When the numbers move, write down three of them: what it reads with nothing happening, with a little happening, and with a lot happening. Your LINE goes between the first two. To react when the reading goes low instead (a dark room), swap HIGH and LOW on the digitalWrite line.

Distance sensor (HC-SR04)? Use this one instead

The any-sensor sketch cannot read it. This one prints the distance in centimetres and lights the LED when something comes closer than LINE.

// distance-led.ino: reads the HC-SR04, prints cm, lights an LED when something is close.

const int TRIG = 9;          // sensor TRIG to D9
const int ECHO = 10;         // sensor ECHO to D10
const int LED = 5;           // LED long leg to D5, short leg through a 220 ohm resistor to GND
const int LINE = 30;         // CHANGE: centimetres where it should react
const int GAP = 5;           // raise this if the LED flickers at the line

bool near = false;           // remembers the last answer between readings

void setup() {
  Serial.begin(115200);
  pinMode(TRIG, OUTPUT);
  pinMode(ECHO, INPUT);
  pinMode(LED, OUTPUT);
}

void loop() {
  digitalWrite(TRIG, LOW);
  delayMicroseconds(2);
  digitalWrite(TRIG, HIGH);                    // a 10 microsecond ping
  delayMicroseconds(10);
  digitalWrite(TRIG, LOW);
  unsigned long us = pulseIn(ECHO, HIGH, 30000);
  float cm = us ? us / 58.0 : 400.0;           // no echo back: call it far away

  if (cm < LINE - GAP) near = true;            // clearly closer than the line
  if (cm > LINE + GAP) near = false;           // clearly back past it
  digitalWrite(LED, near ? HIGH : LOW);       // the response

  Serial.print("cm ");                         // same format bench.html reads
  Serial.println(cm, 1);

  delay(50);
}

3Pick the response

The sketch lights an LED. Swap in any of these. The answer has to be something a visitor can see or hear without you explaining it.

LEDLong leg to D5, short leg through a 220 ohm resistor to GND. Already in the sketch.
BuzzerPlus to D6, minus to GND. In loop(), replace the digitalWrite line: 
if (over) tone(6, 880, 100);
In the distance sketch the word is near.
ServoBrown to GND, red to 5V, orange to D3. 
// top of the file:
#include <Servo.h>
Servo arm;
// inside setup():
arm.attach(3);
// in loop():
arm.write(map(value,0,1023,0,180));
// distance sketch: arm.write(map(cm,5,100,0,180));

4Stuck? Six checks before you raise a hand

  1. No port shows up in the IDE. Try another USB cable. Some cables carry power but no data.
  2. Upload fails with not in sync. Tools, Processor, ATmega328P (Old Bootloader). Unplug, plug back in, upload again.
  3. The Serial Monitor shows garbage. Set the speed in its corner to 115200.
  4. The number is stuck at 0 or 1023. The signal wire is on the wrong pin, or the sensor has no power. Check 5V and GND first. A digital sensor stuck on or off: turn its little screw dial.
  5. The number jumps around with nothing touching it. The signal wire is not really connected. Push it fully into the right breadboard row.
  6. Everything checks out and it still reads nothing. Swap in a spare sensor of the same kind before you rewire anything. Parts do die.

5A sensor that is not on this page

Take a clear photo of the board, both sides, so the labels and the chip are readable. Give it to an AI with this:

This is a sensor board I want to use with an Arduino Nano (5V).
1. What sensor is it?
2. Which pin is power, which is ground, and which is the signal?
3. Is the signal analog, digital, or I2C?
4. Which Nano pin does each wire go to?
5. If it needs a library, which one, and which example sketch should I open?

Then check its answer against the table in step 1. If they disagree, the labels on the board win.
